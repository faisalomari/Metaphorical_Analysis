Executive summary

Do examples help? Bottom line: few-shot examples help Gemini unambiguously (now on all 3 sets, not just 2), help Claude for 2 of 3 example sets, and do not help — or actively hurt — GPT-5.4-mini. A single blanket "yes, few-shot helps" conclusion would be wrong for this subtype/prompt/model combination; the effect is model-dependent.

How much does the choice of examples matter? So example-choice sensitivity is real but concentrated: specifically "Set C differs from A and B" for Claude and GPT, and Gemini shows no significant choice-sensitivity on the primary metric at all. example_sets.json confirms Set C's two example verses are both built on the same root ع-ق-ل (التعقيل) applied to different objects — the leading candidate explanation this pilot was designed to test (see docs/phase4/E1_V2_SET_D.md for the direct follow-up test of that hypothesis), and the data here is consistent with (not proof of) that homogeneity hurting generalization for Claude and GPT. Gemini's insensitivity to the same C-set homogeneity is itself a notable, model-dependent finding.

Model comparison: Cost-adjusted: Claude's much higher cost ($7.09 of the $10.57 total) now looks better-justified on the primary metric for sets A/B than it did on strict/token, where Gemini led outright; cost-conscious choices should weigh which metric is actually decision-relevant for the downstream use case.

a. Design

Poet of interest: أبو نواس. Target sub-element: استعارة فعل (parent مجاز (Trope) — فرع الاستعارة). Pool: 25 poems (5 أبو نواس + 20 other), drawn with seed=43 from a 158-poem candidate pool, 327 verse-units total (persisted at experiments/phase4_e1_v2/config/eval_pool_25.json).

Sets

  • Z — zero-shot baseline: Phase 3's original subtype prompt, one built-in definition example, no injected few-shot examples.
  • A / B / C — Z's prompt plus 2 extra example verses each, drawn from 3 different Abu Nuwas poems (reused unchanged from E1 v1's example_sets.json, seed=42).
  • D — added later to test whether Set C's root-homogeneity (both examples built on ع-ق-ل) explains its underperformance: Example 1 = Set C's example, Example 2 = Set A's second example (different root). Composed programmatically from A/B/C's existing example dicts, never retyped — see e1v2_config.SET_D_SOURCE. Carries a confound: the borrowed Example 2 has one span with an empty analysis note.
  • D2 — the confound-free control for D: Example 1 = same as D, Example 2 = Set B's second example (different root, fully annotated).

5. What this does NOT prove (caveats)
  • Verse is the PRIMARY metric by explicit user decision (2026-10-14), not a project-rule change — CLAUDE.md rule 4's standing warning still applies in full: plain exists/not-exists rewards exists=True regardless of whether the pointed-at span is correct, and §0.5's verdict (especially Claude's flip from "no support" to "clear support") is the concrete cost/benefit of that choice, not a more objectively "correct" result than the secondary metrics.
  • 1 run per cell, no noise baseline (CLAUDE.md rule 2) — every point estimate and CI above reflects a single run; a second run could shift set rankings, exactly as the documented Kenning/Periphrasis 8×→½ precedent shows for this kind of design.
  • Example-2 note confound: Set D's example 2 (borrowed from A) has an empty analysis note on one of its spans — the only example among A/B/C/D that is partially unannotated. D's result is therefore a joint test of "different root" AND "possibly weaker annotation," not an isolated root-diversity manipulation. D2 (fully annotated on both examples) is the cleaner test, and its results sometimes diverge from D's (most notably for Claude).
  • 25 poems, 327 verse-units — the same small pool as Z/A/B/C; bootstrap CIs are correspondingly wide, and several "ns" results above likely reflect limited power, not a confirmed null effect.
  • n=2 examples per set — this experiment only tested one specific swap (C's example 1 + one other example). It does not establish that "any diverse 2nd example" works, or that 3+ diverse examples would do better; it tests exactly the two swaps defined in §0, nothing more general.
  • TEST is unaffected — this entire pilot runs on data/ali_poems/, a separate corpus from Phase 1's frozen DEV/TEST split; nothing here touches any frozen Phase 1 number.
