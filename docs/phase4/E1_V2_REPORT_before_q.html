Executive summary

Do examples help? Bottom line: few-shot examples help Gemini unambiguously (now on all 3 sets, not just 2), help Claude for 2 of 3 example sets, and do not help — or actively hurt — GPT-5.4-mini. A single blanket "yes, few-shot helps" conclusion would be wrong for this subtype/prompt/model combination; the effect is model-dependent.

How much does the choice of examples matter? So example-choice sensitivity is real but concentrated: specifically "Set C differs from A and B" for Claude and GPT, and Gemini shows no significant choice-sensitivity on the primary metric at all. example_sets.json confirms Set C's two example verses are both built on the same root ع-ق-ل (التعقيل) applied to different objects — the leading candidate explanation this pilot was designed to test (see docs/phase4/E1_V2_SET_D.md for the direct follow-up test of that hypothesis), and the data here is consistent with (not proof of) that homogeneity hurting generalization for Claude and GPT. Gemini's insensitivity to the same C-set homogeneity is itself a notable, model-dependent finding.

Model comparison: Cost-adjusted: Claude's much higher cost ($7.09 of the $10.57 total) now looks better-justified on the primary metric for sets A/B than it did on strict/token, where Gemini led outright; cost-conscious choices should weigh which metric is actually decision-relevant for the downstream use case.

a. Design

Poet of interest: أبو نواس. Target sub-element: استعارة فعل (parent مجاز (Trope) — فرع الاستعارة). Pool: 25 poems (5 أبو نواس + 20 other), drawn with seed=43 from a 158-poem candidate pool, 327 verse-units total (persisted at experiments/phase4_e1_v2/config/eval_pool_25.json).

Sets

  • Z — zero-shot baseline: Phase 3's original subtype prompt, one built-in definition example, no injected few-shot examples.
  • A / B / C — Z's prompt plus 2 extra example verses each, drawn from 3 different Abu Nuwas poems (reused unchanged from E1 v1's example_sets.json, seed=42).
  • D — added later to test whether Set C's root-homogeneity (both examples built on ع-ق-ل) explains its underperformance: Example 1 = Set C's example, Example 2 = Set A's second example (different root). Composed programmatically from A/B/C's existing example dicts, never retyped — see e1v2_config.SET_D_SOURCE. Carries a confound: the borrowed Example 2 has one span with an empty analysis note.
  • D2 — the confound-free control for D: Example 1 = same as D, Example 2 = Set B's second example (different root, fully annotated).

  • Verse is the PRIMARY metric by explicit user decision (2026-10-14), not a project-rule change — CLAUDE.md rule 4's standing warning still applies in full: plain exists/not-exists rewards exists=True regardless of whether the pointed-at span is correct, and §0.5's verdict (especially Claude's flip from "no support" to "clear support") is the concrete cost/benefit of that choice, not a more objectively "correct" result than the secondary metrics.

  • Example-2 note confound: Set D's example 2 (borrowed from A) has an empty analysis note on one of its spans — the only example among A/B/C/D that is partially unannotated. 6. Plain answer — does majority voting beat the best single model?

No, not on any set or criterion. The ensemble is never significantly better than that set's best single model (§3's "vs [best model]" cell is ns in every row except Z-verse, where the ensemble is significantly worse than GPT-5.4-mini's zero-shot F1). On the primary verse metric the ensemble sits close to the best single model — sometimes marginally above its point estimate (D: 0.577 vs. Claude's 0.562), sometimes marginally below (D2: 0.550 vs. Claude's 0.568) — but never with a CI that excludes 0.

Does it beat the average of the 3 single models? On verse (primary), yes, consistently — the ensemble's F1 point estimate exceeds the average of the 3 singles in all 6 sets (by +0.010 to +0.043), and §3 shows this is often a *significant* improvement over the two weaker models specifically (e.g., Z: ensemble beats Claude and Gemini significantly, loses to GPT significantly — GPT's zero-shot F1 of 0.549 is simply far above the other two). On strict/token (secondary), the opposite: the ensemble's F1 is below the average of the 3 singles in every single set, because the declared span-agreement rule (§0) is strictly harder to satisfy than plain existence voting.

Does this agree with Phase 1's ensemble finding? PROJECT_STATE.md §3e found that majority-vote-across-models gave no improvement over the best single model, and was sometimes worse. This result agrees on the primary metric (no significant improvement over best, one case of significantly worse) and strengthens it on the secondary metrics, where the ensemble is significantly worse than the best single model in most sets (5 of 6 on strict, 5 of 6 on token). The overall picture across both Phase 1 (different task/elements) and this Phase 4 pilot (this subtype, this prompt, this model trio) is consistent: majority voting across these 3 models is not a free F1 win here, and can actively hurt when the per-model disagreement is about *where* the figure is rather than *whether* it exists.

Caveats
  • One run per (set, poem, verse, model) cell — same as every other number in this pilot (CLAUDE.md rule 2's noise precedent applies to the ensemble exactly as it does to each single model; a second run could shift any individual CI, though the ensemble vote itself is a deterministic function of the 3 already-run cells, not a new source of run-to-run noise).
  • 25 poems total, أبو نواس n=5 — the abu_nuwas split in §1/§4 is indicative only, same caveat as every other abu_nuwas/other breakdown in this pilot.
  • Voting is on the user-chosen verse criterion for the primary metric; the secondary strict/token ensemble uses its own declared match-agreement rule (§0), which is not the only possible way to define an "ensemble span" — see the stated limitation there.
  • CLAUDE.md rule 4's standing caveat still applies to verse as a diagnostic: it can reward exists=True regardless of span correctness. The disagreement between §3's verse-primary and strict/token-secondary verdicts here (ensemble competitive-or-better on verse, consistently worse on strict/token) is itself an instance of exactly that caveat, not a new phenomenon.

3. Where verse (primary) and strict/token (secondary) disagree for Opus

This is the opposite of the project's usual pattern (CLAUDE.md rule 4 warns that verse-level scoring tends to look *better* than span-level scoring because it rewards "present" regardless of whether the model points at the right text). Here Opus's advantage is far larger and uniformly significant on the secondary span-level metrics, and mostly washes out to ns on the primary verse metric — against Sonnet and the ensemble specifically, verse is ns while strict/token are both clearly SIG. The reason is visible in the raw counts: Opus's verse-level recall is *lower* than Sonnet's (0.654 vs 0.819) because Opus says "no sub-element here" more often — but when Opus does say "yes," it is far more often pointing at the actually-correct span (its precision is higher everywhere, and its strict/token F1s are higher than every other model's by a wide, significant margin). Sonnet's higher verse-recall inflates its verse F1 relative to its own much weaker span-level accuracy (strict F1=0.257, well below Opus's 0.387) — exactly the exists- regardless-of-span-correctness effect CLAUDE.md rule 4 describes, just showing up as a *disadvantage* for the metric's usual beneficiary here, not Opus.

1. Design
1.1 Poet/example selection (declared before any API call, seed=42)

Eligibility rule: a poem is a candidate example source for poet P iff it is not one of the 5 frozen Phase 1 poems, not the no-text poem, and not one of v1's own 3 Abu-Nuwas-only example-source poems (EXAMPLE_POEM_IDS) — and, only for أبو نواس, also not one of the original eval_pool.json's 10 Abu Nuwas poems (so Abu Nuwas could appear as one of the poets, but only via a poem outside the existing eval pool and the existing fewshot examples, as the supervisor's design asked). A verse is eligible iff it carries ≥1 annotation with subtype == "استعارة فعل" (exact match) and a non-empty analysis note. A poet is eligible iff ≥1 of their candidate poems has ≥1 eligible verse.

47 eligible poets were found, spanning 8 periods: العصر الأموي=16, العصر العباسي=12, العصر الجاهلي=7, مخضرم=5, مخضرم الدولتين=2, blank/unknown=3, الخلفاء الراشدون=1, العصر المملوكي=1.

Poet-selection order is a deterministic period-diversity round robin — NOT randomized: periods are visited in a fixed order (chronological-ish: جاهلي → مخضرم → مخضرم الدولتين → أموي → عباسي → any other period → blank), poets within a period ordered by poet_id, cycling through periods and taking the next poet from each until enough are collected. F5 = the first 5 poets in this order, F10 = the first 10 (so F5's poets are a strict prefix of F10's — guaranteed by construction, not by chance), and the costed-but-not-run optional F5b = poets 11–15 (5 *other* poets, disjoint from F10, to separate "more examples" from "which examples" a second way). Abu Nuwas was not selected by this round robin (other عباسي-period poets filled those slots first by poet_id order) — so the Abu-Nuwas-specific exclusion rule above never actually had to fire for this draw.

Only the per-poet verse draw is randomized: one random.seed(42) call, then one random.sample(eligible_verses_for_poet, 1) per poet in selection order — sequential RNG consumption that is never reseeded mid-draw, so F5's 5 draws are byte-identical whether or not F10 (or F5b) is ever built.

5. Plain answer

Do more examples from different poets help? Does 10 beat 5?

Mostly no, with one exception. On the full 1000-verse pool — the reliable, primary comparison — 8 of 9 model×criterion combinations show no significant difference between F5 and F10. The one exception is Claude on the primary verse metric, where F10 significantly beats F5 (+0.027 F1) — but even there, Claude's own strict/token numbers for the same comparison are not significant, and the per-poem sign count (23 poems favor F10, 15 favor F5, 12 tied) shows a real but not overwhelming tilt, not a clean sweep. Going from 5 to 10 different-poet examples is, for GPT and Gemini, statistically indistinguishable from noise in every one of 6 criterion checks; for Claude it may buy a small amount on the primary metric specifically.

Does it beat the existing 2-example sets (A/B/C/D)? This can only be checked on a thin, Abu-Nuwas-skewed 9-poem overlap, so read it as indicative, not conclusive — but the model-dependence already well-documented in E1_V2_RESULTS.md for Z vs. A/B/C continues cleanly into F5/F10: Gemini and Claude both get a real, often-significant lift from *any* fewshot block (2-example or multi-poet) over zero-shot Z, and the multi-poet sets sit roughly level with (Claude) or somewhat above (Gemini, on verse) the best 2-example sets — more examples from more poets does not clearly hurt these two models, and may help Gemini a little. GPT is the opposite story, sharper here than it already was for Set C: F5/F10 are significantly worse than A/B/D on this subset (and no better than C, GPT's already-identified weak set) — for GPT specifically, piling on more examples from more poets looks actively counterproductive, consistent with GPT's established pattern (E1_V2_RESULTS.md Q1) of not benefiting from fewshot examples at all and sometimes being actively hurt by them.

Caveats (same discipline as every other table in this project):

  • One run per cell, one draw of poets/verses, no noise baseline. Nothing here has been replicated a second time; a single comparative result (especially the one SIG F5-vs-F10 finding) should not be treated as fully settled, per the project's own standing Kenning/Periphrasis precedent (CLAUDE.md rule 2).
  • The vs-A/B/C/D comparison rests on only 9 poems, disproportionately Abu Nuwas (56% vs. 20% elsewhere) — a different overlap sample could plausibly shift GPT's apparent "multi-poet hurts" finding or Gemini's "multi-poet helps" finding in either direction. Running the optional Z add-on (Z on the full 50-poem pool, ~$6.45, not yet run) would at least remove the Z side of this thinness, though A/B/C/D would remain pool_25-only regardless.
  • F5's poet/verse selection is one specific deterministic draw (period-diversity round robin + one seeded verse per poet) — a different period-ordering rule or a different seed could select different poets/verses entirely; no sensitivity check against an alternative selection rule was run.

A poem is a candidate example source iff not in: NO_TEXT_POEM_ID, the 5 Phase-1-frozen ALREADY_USED_POEM_IDS, the 3 Abu-Nuwas v1 EXAMPLE_POEM_IDS, the 10 F5/F10 example-source poems, or any of eval_pool_25.json's 25 poems (the pool these six sets are themselves evaluated on). A poet is eligible iff not القرآن الكريم (not an individual), has ≥1 candidate verse carrying a genuine (note_quality()-passing) استعارة فعل annotation, and has confidence high/medium in poet_dates.csv ("poets need a reliable death year," per the task).

Declared deviation: applying Part 1's full-36-poet-corpus year-threshold bands directly to this smaller, much-more-restricted selection population crashed (pool exhausted) — most of the full axis's extreme-dated poets (النابغة الذبياني، الأعشى ميمون، امرؤ القيس, among others) turn out to have zero usable candidate verses in this corpus (their استعارة فعل annotations carry empty analysis notes, failing eligibility before note_quality() even runs). Only 14 poets survive (dated + confidence high/medium + eligible), too few for the full-axis bands' roles to avoid competing for the same 2–3 poets. Fix (experiments/phase4_e1_v2/eras_examples.py): compute bands by rank within this 14-poet population instead of by absolute year — earliest_extreme/latest_extreme = the first/last ceil(0.15×14)=3 poets by rank; middle_band = the 4 poets (exactly enough for M1+M2) whose rank is nearest the population's center; h1_pool/h2_pool = each half's remaining ranks after the extreme/middle roles are removed. For this run the five resulting pools came out pairwise disjoint by construction (verified programmatically) — this changes nothing about Part 1's own full-corpus ERAS_ANALYTICS.md bands.

5. Plain answer

Does the era of the example poets matter (middle vs. extremes vs. halves)?

Mixed, and the signal is often no larger than pure example-choice noise. Looking at the pooled cross-category comparisons (§3.2) against the within-pair noise from swapping just the *specific poets* within the same band (§3.1):

  • Claude: era does matter in one clear sense — the middle band (M, pooled) and the two half- middles (H) both significantly beat the extremes (E) on verse (M−E +0.052 SIG, E−H −0.044 SIG, i.e. H>E too), while M vs H is not significant. But the within-band noise is *at least as large*: M1 vs M2 (−0.069 SIG) and E1 vs E2 (−0.087 SIG) are both themselves significant and larger in magnitude than the M−E effect (+0.052) that "era matters" rests on. So for Claude, *which 2 specific poets you draw* is at least as consequential as *which band they come from*.
  • GPT: no era signal at all — every pooled cross-category comparison is ns (M−E, M−H, E−H all non-significant), while M1 vs M2 (−0.068 SIG) is itself significant. For GPT, the only reliable effect in this whole design is plain poet/verse choice noise, not era.
  • Gemini: the cleanest case for a real era effect — H (half-middles) significantly beats both M (−0.042 SIG) and E (−0.044 SIG) on the pooled comparison, and none of the three within-band noise checks (M1-M2, E1-E2, H1-H2) reach significance except H1 vs H2 itself (+0.078 SIG) — ironically the one within-pair gap that *is* significant belongs to the band that otherwise looks like the winner, which tempers how clean this "Gemini sees a real era effect" read actually is.

Bottom line: there is no model-general answer. Claude and Gemini each show *some* pooled band-level signal, but by two different, non-overlapping routes (Claude: middle/halves beat extremes; Gemini: halves beat both middle and extremes), and in both cases at least one within-band noise check is comparable in size to the signal. GPT shows no era effect whatsoever — only the ordinary draw-to-draw noise already documented everywhere else in this project (CLAUDE.md rule 2's Kenning/Periphrasis precedent). None of the six sets catastrophically underperforms the existing A/B/D2 sets except E1 specifically (earliest+latest poet pairing: طرفة بن العبد + الصنوبري), which is significantly worse than A/B/D2 for all three models — the one consistent cross-model finding in this whole design, though it is a single poet pairing, not a property of "extremes" as a category (E2's different earliest+latest pairing does not show the same pattern for GPT/Gemini, only partially for Claude).

Caveats (same discipline as every other table in this project):

  • One run per cell, one draw of poets/verses, no noise baseline — every number above, significant or not, is indicative only (CLAUDE.md rule 2).
  • One specific rank-based draw (seed=42, the eligibility/confidence/note-quality filters declared in §1.3) — a different seed, a looser note filter, or a different confidence threshold could plausibly select different poets and shift the within-band noise estimates (which are themselves based on just 2 poets per band) substantially; §3.1's within-pair numbers are a single, small-n estimate of that noise, not a stable baseline.
  • Only 14 poets survived the selection-eligibility restriction out of 36 dated corpus poets — this design answers "does era matter among the poets whose annotations happen to carry usable analysis notes in this corpus," not "does era matter among all poets in the corpus."
  • Abu Nuwas / other splits, strict/token secondary criteria, and per-poem diff signs are all in results/phase4_e1_v2/analysis_report_eras.json but not reproduced in this document for length; every verse-primary conclusion above should be read alongside CLAUDE.md rule 4's standing caveat that plain exists/not-exists can diverge from span-level correctness.
